# Remote MCP Server PoC (Cloudflare Workers)

**Proof of concept, no SLA.** This is the open-source core of [pmo.run](https://pmo.run) served
over remote MCP (Streamable HTTP) **and plain REST, from one core,** on Cloudflare Workers — a
deployment-pattern validation, not a product. It is stateless by design: no storage bindings, no
persistence, no request-content logging. The paid pmo.run product is a separate system and does
not run from this code.

If you just want the decision-logic tools locally, use the stdio server instead:
`uvx pmorun-mcp` ([docs](https://pmo.run/en/docs/mcp-server/)).

## What It Serves

One tool, `estimate_task_duration` — the textbook PERT three-point estimate
(`expected = (O + 4M + P) / 6`, `std_dev = (P − O) / 6`, with 68/95/99% ranges), ported from
[`app/pert/core.py`](../../app/pert/core.py) and parity-tested against fixtures generated by the
Python module. The insight-tag adjustment path is deliberately not ported.

Both surfaces expose the same single tool:

- **MCP**: `POST /mcp` (Streamable HTTP, JSON-RPC)
- **REST**: `POST /api/pert` — same input object, same result object, HTTP status codes instead
  of JSON-RPC error wrapping

```bash
curl -s https://<your-worker>.workers.dev/api/pert \
  -H "Authorization: Bearer <your-token>" -H "Content-Type: application/json" \
  -d '{"optimistic": 2, "most_likely": 4, "pessimistic": 8}'
```

## Layout

- `src/pert.ts` — the PERT port (pure functions, no Workers APIs)
- `src/round.ts` — half-to-even rounding, matching Python's `round()`. A copy of
  `site/src/lib/round.ts`; keep the two in step
- `src/tools.ts` — shared validation + tool execution seam; both surfaces call this, so their
  behaviour cannot drift apart
- `src/mcp.ts` — minimal stateless MCP server: JSON-RPC over Streamable HTTP, no SDK dependency
- `src/rest.ts` — the REST surface: one route over the same core
- `src/index.ts` — Worker entry point: bearer-token gate (fails closed, shared by both surfaces),
  routing
- `test/` — parity suite (Python-generated fixtures), protocol/auth tests, and cross-surface
  parity (REST vs MCP must return byte-identical results)

## Develop and Test

```bash
npm ci
npm test          # vitest: parity + protocol + auth
npm run typecheck # tsc --noEmit
```

To regenerate the parity fixtures after changing the Python module, run from the repository root:

```bash
uv run python examples/remote-mcp/scripts/generate_fixtures.py
```

CI runs that generator in the `pytest` job and fails on a non-empty diff, so a
core change that leaves these fixtures behind goes red rather than netting this
port against a core that no longer exists.

## Deploy (Self-Host)

Requires a Cloudflare account API token (Workers Scripts:Edit) and the account ID in the
environment — neither is committed:

```bash
export CLOUDFLARE_API_TOKEN=...   # never commit this
export CLOUDFLARE_ACCOUNT_ID=...

npm run deploy                                    # wrangler deploy
openssl rand -base64 32 | npx wrangler secret put AUTH_TOKEN
```

The worker refuses to serve `/mcp` and `/api/pert` (HTTP 503) until `AUTH_TOKEN` is set — an
unset secret must never mean an open endpoint. Add Cloudflare rate limiting on the routes as a
second layer.

## Connect a Client

Claude Code (supports custom headers):

```bash
claude mcp add pmorun-poc --transport http \
  https://pmorun-mcp-poc.<your-subdomain>.workers.dev/mcp \
  --header "Authorization: Bearer <your-token>"
```

Or the MCP Inspector with the same URL and header. claude.ai web connectors require an OAuth
flow this PoC deliberately does not implement.
